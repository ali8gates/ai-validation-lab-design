# The Multi Specialty Pattern

This work started in cardiovascular care because that is where the data and the pathways were strongest. The structure underneath is not specialty specific, and it was designed from the beginning to be lifted.

## Why start narrow

One specialty, a small number of high value pathways, run end to end. Guideline to evaluation design to validation to evidence to guideline revision.

Running the whole loop once on a narrow scope teaches more than running the first half of it across six specialties. Depth surfaces the parts that do not work, and breadth hides them. The temptation is always to announce coverage early. That produces a directory of shallow reports and no evidence that the loop closes.

## What generalizes and what does not

Three pieces are pluggable, and everything else is shared.

**Pathway definitions.** Specialty specific and owned by the people who own the guideline. This is the seam. Add a new specialty by adding pathway definitions, not by changing the engine.

**Registry connectors.** Every registry has its own schema, refresh cadence, and access terms. The connector normalizes into a common internal representation. That layer is real work per source and it is where most of the integration cost lives.

**Scenario libraries.** Built per pathway with clinical review, versioned, partly held back.

**Shared across all specialties.** The evaluation engine, the metric definitions, the subgroup framework, the report structure, the monitoring checks, the protocol template, and the governance process. That is the majority of the system, which is the point.

## Sequencing across specialties

1. Prove the loop in one specialty and publish the result.
2. Add a second specialty that shares the data substrate, so the connector work is small and the engine gets tested against a genuinely different pathway shape.
3. Only then add specialties that need new data sources, since that is the expensive direction.

The second step matters more than it looks. The first cross specialty case is what tells you whether the abstractions hold or whether the engine quietly encoded cardiovascular assumptions.

## What a coordinating body gets from this

For an organization convening several specialty societies, the shared layer is the asset. Each society brings its own pathways, its own reviewers, and its own registry relationships. Nobody rebuilds the evaluation engine, the report format, or the governance model.

That also produces the thing no single society can produce alone. Results that are comparable across specialties because they were generated by the same engine against the same metric definitions and the same report structure. Comparability is the argument for coordinating in the first place, and it only exists if the shared layer is genuinely shared rather than forked per society.

## The failure mode to watch

Federation without a shared engine. Every society builds its own version, results stop being comparable, and the coordinating layer becomes a website that links to nine different report formats. Avoiding that requires the engine and the report structure to be governed centrally while pathways and clinical judgment stay local. That split is a governance decision, not a technical one, and it has to be settled before the second specialty joins rather than after.
